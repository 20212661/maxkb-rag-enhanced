# L1 精确问答缓存 v1

通过 `MAXKB_QA_L1_CACHE_ENABLED` 控制，默认开启。Redis 有效期为 1800 秒并增加 ±180 秒抖动。仅接收已配置回答模型、无对话历史、dialogue_number 为 0、关闭问题优化及长期记忆的简单 RAG 请求。附件、表单、重新生成、工具、MCP、技能和子应用调用会跳过准入。

## 命名空间

键包含 workspace、应用 ID、实际发布版本内容哈希、排序后的知识库版本、检索设置、排除文档、分块配置指纹、回答模型参数与提示词哈希、当前用户及授权知识库范围。问题使用实际文本的 SHA256，保留大小写、标点、数字和否定词。

命中前执行现有聊天鉴权、应用资源授权检查，再核对知识库范围和版本。引用段落的归属、启用状态、标题、正文和文档名再次校验。完整回答生成后，只有检索时的引用与当前正文一致且版本仍有效才会发布缓存。

Redis single-flight 采用持有者令牌、120 秒租约和续租。等待上限为 1 秒，超过预算可独立计算，重复发布保留首份完整结果。失败、中断及无检索证据的结果会跳过发布。Redis 读写失败时执行正常问答。

缓存命中使用本次会话和新消息 ID，通过现有聊天记录保存逻辑生成记录，保留引用并更新访问次数。模型 token 用量记为 0，支持流式与非流式响应。

## 知识库版本

`knowledge_cache_state` 的每个知识库只有一条记录，初始版本为 0。历史知识库由迁移初始化，新知识库首次向量变更时创建记录。

版本递增集中在 BaseVectorStore 的保存、删除和更新封装中，使用 `F()` 更新。向量与版本在同一数据库事务提交或回滚。启停操作通过更新入口处理，向量迁移同时使源、目标知识库失效。

更新和删除前锁定本次处理的向量记录，固定其 ID 和知识库归属，避免并发迁移使版本递增遗漏目标知识库。

## 验证

```bash
python eval/verify_cache.py --phase l1 --config eval/.local-week3-D.json
python eval/verify_l1.py --config eval/.local-week3-D.json
```

第一条命令重新保存冻结语料，在所有缓存关闭时运行 60 题逐题回归。

第二条命令经过正式发布版本、会话开启和 ChatSerializers 聊天入口，使用真实本地向量检索和离线回答模型夹具检查生成、引用、聊天记录和缓存复用。夹具输出固定文本，P50/P95 描述该验证链路。真实大模型的回答质量、响应时间及费用需要使用实际 API 配置另行测量。临时应用、模型和聊天记录在完成后清理。

### 真实模型对照

在现有评测环境的模型管理中保存 DeepSeek 或通义千问的 API Key，然后使用该模型 ID 运行。

```bash
python eval/verify_l1.py --model-id YOUR_LLM_MODEL_ID \
  --output eval/results/week5/l1-api.json
```

默认选择 12 题，使用相同检索与回答配置依次执行缓存关闭、首遍填充和第二遍命中。真实模型模式全部使用流式响应，记录完整响应和首个非空可见内容的 P50/P95。统计范围包括 ChatSerializers、真实本地检索、回答 API 及聊天记录处理。

供应商 token 用量通过 LangChain 回调读取，另存框架 token 统计。若 API 未返回用量，供应商总 token 记为空。重复请求命中时业务模型调用和 token 消耗为 0。结果保留回答和证据 ID 供复核，临时应用和会话在结束后清理，用户原有模型保留。

可通过 `--questions` 指定 10–20 个开发集问题 ID，通过 `--max-output-tokens` 设置实验应用中的模型输出参数。只有模型参数表支持的 `max_tokens` 项会覆盖。2026-11-13 已完成 DeepSeek Flash 的 12 题真实对照，数据见 [API 实验报告](../eval/results/week5/README.md)。

## 已知限制与 v2

- 直接修改 Embedding 的 SQL 或 ORM 操作会绕过版本封装。现有 `tokenize_by_paragraph` 的关键词 `bulk_update` 属于这一范围。
- 文档配置和知识库配置中，未触发向量存储操作、也未进入当前命名空间或引用校验的字段，缺少自动失效事件。
- 重建期间可查询到中间索引，v1 依赖向量变更版本和引用校验，完整重建快照与 generation 归入 v2。
- 模型配置跨进程实例失效、缓存容量清理、跨用户授权范围共享、在线 L2 和 QAAnswerCache 归入 v2。
- 远端模型升级或服务地址切换时增加 `MAXKB_EMBEDDING_CACHE_EPOCH`，并刷新各进程实例。该代次也进入 L1 命名空间。
- 新增文件的 Ruff 检查通过。涉及的 `base_chat_step.py` 存在两条既有 Ruff 问题，分别为第 156 行的 F841 和第 190 行的 F541。
