# 本机应用真实 HTTP 测试

2026-11-13 对现有的“Day3-IT支持与安全运维助手”执行测试。为使该应用可用，已通过管理 API 绑定已保存的 DeepSeek Flash、发布应用，并开启来源展示。关联原有 Day3 知识库，包含 10 份公开文档。

本轮模型为 `deepseek-flash`，temperature 0.2、max_tokens 512、reasoning_effort `none`。请求经过匿名应用认证、公开聊天 HTTP 接口、本地检索和真实 DeepSeek API。

## 接口和缓存结果

| 测试 | 结果 |
| --- | --- |
| SSE 流式聊天 | 4/4 返回 HTTP 200，收到结束帧和非空回答 |
| 非流式聊天 | 3/3 返回 HTTP 200 和非空回答 |
| 有资料问题的来源返回 | 6/6 返回 5 个检索段落及文档名，包含重复请求 |
| 完全重复问题的 L1 回放 | 2/2 命中，回答和来源与首遍一致 |
| 回放 token | 两次均为输入 0、输出 0 |
| 消息记录 | 7 个 ID 全部不同 |
| 无天气资料的问题 | 返回资料不足，来源列表为空 |
| 发布页 | HTTP 200，返回包含脚本入口的 HTML |

每次提问均新建会话，并复用同一匿名用户身份。当前 L1 的准入要求无历史消息。重复负载由实验构造，2/2 命中仅描述本轮测试。页面浏览器渲染和点击操作尚未验证。

| 问题 | 首遍总响应 | 重复总响应 | 首遍输入 / 输出 token | 重复输入 / 输出 token |
| --- | ---: | ---: | ---: | ---: |
| 中卫市信息安全责任原则 | 2889.9 ms | 52.5 ms | 1295 / 41 | 0 / 0 |
| 中卫市机房非授权区陪同 | 1776.8 ms | 104.0 ms | 2300 / 124 | 0 / 0 |

耗时包含公开 HTTP 接口响应和流式消费，为单次本地测量。7 次请求在框架消息记录中的 token 合计为 7770，供应商账单应以其控制台为准。

## 回答核对

| 问题 | 观察 |
| --- | --- |
| 中卫市信息安全责任原则 | 正确回答“谁主管、谁负责” |
| 河南水利与环境职业学院报告表，“是否备案”选是 | 正确回答继续填写“备案号” |
| 明天上海的准确气温 | 明确说明资料不足 |
| 中卫市机房非授权区陪同 | 已检索到中卫市制度对应段落，也提到了授权工作区人员陪同，但错误地认为该条款不能归属于中卫市 |
| 信阳农林学院病毒无法清除时联系谁 | 已检索到目标文档，也给出有关产品供应商的流程，但对该流程是否属于信阳农林学院保留了确认意见 |

两道单位归属题需要继续改进。检查当前 SIMPLE 提示词构造发现，传入模型的每段资料仅包含段落标题和正文，文档名保存在引用元数据中。应用的提示词同时要求区分各单位制度，缺少文档名可能造成上述归属确认问题。这是基于提示词构造与本轮回答的原因推断。

本轮完成了接口和缓存验证，回答质量保留上述两项问题。原始回答、引用段落、时间及 token 见 [live-application-test.json](live-application-test.json)。

## 记录读取说明

测试初稿将管理接口响应误按内部 `ChatRecord.details` 结构读取，导致来源和缓存字段漏读。已改用接口实际返回的 `paragraph_list` 和 `execution_details`，并在消息记录写入完成后重新读取，校验来源、缓存标记、token 和消息 ID。原始请求计时保持不变。
